# 引用续聊

**引用消息继续原话题，不引用开启新话题。默认关闭。**

面向 AstrBot **4.28.0、Python 3.12+、飞书（lark）内置 Agent** 的独立插件。
不需要安装飞书 Agent 卡片插件，不导入它的代码、不读取它的数据，也不修改 AstrBot 核心。

当前为 **0.2.1**。离线单元测试和真实 AstrBot 对话管理器/飞书 SDK 集成检查通过；尚未连接真实飞书应用做端到端验收，不代表已经上架商店。

## 怎么使用

1. 在 AstrBot 插件管理中从本仓库安装，或将代码放入 `data/plugins/astrbot_plugin_quote_topics` 后加载。
2. 打开插件配置，开启总开关，再分别开启群聊或私聊。
3. 建议先填写一个测试群的 `oc_...` 群号。默认“全部群聊”关闭、指定列表为空，因此不会影响任何群。
4. 在群里按原有方式 @机器人提问。引用原始提问或机器人回复并再次触发机器人，就继续该话题。
5. 发送 `/话题状态` 检查当前会话的配置。

| 操作 | 结果 |
| --- | --- |
| 不引用，直接触发机器人 | 新建话题，保留旧话题 |
| 引用已登记的原始提问或后续提问 | 继续对应话题 |
| 引用机器人普通回复、卡片或流式卡片 | 校验飞书消息关系后继续对应话题 |
| 同群另一位成员引用 | 共同接续，历史保留发言人账号和昵称 |
| 私聊引用自己的旧提问或机器人回复 | 只恢复该用户在该机器人下的话题 |
| 引用未知消息、安装前旧消息、已清理话题 | 明确提示无法恢复，不调用最近话题回答 |
| 不引用发送“再详细一点” | **新话题**，不会接续上一轮 |

引用最初的提问也会接续该话题的**最新历史**，不是回退到当时或创建分支。
原来的 @、唤醒词、权限和触发规则继续生效。普通群聊以及插件管理指令不会因此创建话题。
新话题不携带旧聊天历史，但会保留原选择的人格；模型、工具仍由 AstrBot 配置决定。

## 自动总结话题标题

在插件配置中开启 **自动总结话题标题**（`auto_topic_title`），保存配置。默认关闭。

话题有问答记录后，后台使用当前会话配置的模型，将“引用话题 + 编号”概括成类似“飞书插件安装排查”的短标题，在 AstrBot 对话列表刷新后可见。不会向飞书发送总结，也不会压缩或替换聊天历史。

- 每个话题成功生成一次；手动修改过的普通标题会保留。
- 每次尝试会额外调用模型；主模型失败时按当前会话内置 Agent 的备用模型列表依次尝试，会消耗模型额度。仅提取该话题前几条文字，跳过工具结果和图片。
- 已有的编号话题在下次引用续聊后补生成；不批量扫描历史，也不处理其他来源的“无标题对话”。
- 模型不可用、超时或返回无效标题时保留原名，下次续聊再尝试。
- 后台最多同时生成两个标题，最多容纳八个任务；繁忙时跳过，等待下次续聊。不会占用群聊处理锁。
- 关闭开关后停止新增标题；已生成的标题保留。插件卸载会取消尚未完成的标题任务。
- 此功能继续独立于飞书 Agent 卡片插件，无需增加第三方依赖。

## 为什么不依赖卡片插件

AstrBot 4.28.0 的飞书发送辅助接口只返回发送成功与否，不返回新消息编号。
本插件没有替换发送接口，也没有接管卡片渲染。

处理方式是：

1. 每次实际进入内置 Agent 的提问先登记“消息编号 → AstrBot 对话编号”。
2. 用户引用已登记的提问时，直接从本地数据库恢复。
3. 用户引用尚未登记的机器人回复时，通过当前 AstrBot 飞书客户端读取这条消息。
4. 同时校验聊天编号、发送者类型，以及机器人 Open ID 或应用 App ID。
5. 沿 `parent_id` 找到已登记的提问，缓存机器人回复的关联。不会根据文字、`root_id` 或最近话题猜测。

因此普通文本、原生卡片、原生流式卡片，以及以“回复原始提问”方式发送的第三方卡片，都能使用同一条恢复路径。第一次恢复机器人回复可能多一次飞书 API 查询，缓存后无需查询。

### 必须说明的限制

- **需要飞书读取消息权限。** 复用 AstrBot 已有应用和客户端，不新增密钥、不另开长连接。如果读取失败、消息被删除或身份无法确认，会停止恢复并提示；可以改为引用已登记的原始提问。
- **主动发送或未保留回复关系的消息无法自动恢复。** 这包括某些第三方插件通过创建新消息发送的通知。若要支持此类发送方式，需要将来增加可选的发送回执接入；当前没有要求卡片插件修改。
- **卡片按钮、表单提交不是“引用消息”。** 首版不适配它们的续聊行为。若第三方插件自行构造模型请求，本插件会在能检测到冲突时拒绝处理，避免静默串话。
- **仅支持内置 Agent 的标准消息处理链。** Dify、Coze、其他执行器，以及绕过标准管道自行调用模型的插件不在支持范围内；请不要对这些会话启用本插件。
- **其他上下文来源需单独处理。** 群聊长期记忆、自动注入全群聊天记录的插件可能把其他话题内容重新加进提示词。本插件隔离 AstrBot 对话历史，不承诺隔离这些额外来源。要求严格隔离时，请在启用范围内关闭它们。
- **同群串行处理。** 包括不同群成员对应不同 AstrBot 会话 ID 的情况；不同群、不同私聊可并行。排队最长 120 秒，查询引用最长 12 秒，超时明确提示重试。首版不支持多个 AstrBot 进程共享同一个插件数据库。
- **避免在生成过程中执行切换/删除对话指令，或同时启用其他会话路由插件。** 本插件检查模型请求的对话编号，但不能控制其他插件在检查之后的修改。
- **不自动清理历史或索引。** 重启和插件更新保留数据；长期使用时数据会增长。第一版没有清理管理界面或自动保留期限。

## 配置

| 配置键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | false | 总开关 |
| `platform_ids` | [] | 平台实例 ID；空表示不限制实例 |
| `enable_group` / `enable_private` | false | 群聊、私聊独立开关 |
| `group_all` / `private_all` | false | 是否启用全部群或全部私聊 |
| `group_ids` | [] | 指定群的飞书聊天 ID（oc_...） |
| `private_ids` | [] | 指定用户的飞书 Open ID（ou_...） |
| `excluded_group_ids` / `excluded_private_ids` | [] | 排除列表，优先级最高 |

当“全部”关闭且指定列表为空时，不启用任何会话。排除项在所选平台实例中生效。
配置仅在新请求进入时使用；管理者应等正在生成的请求完成后再更改模式或卸载。

## 数据、备份与失败恢复

索引位于 `data/plugin_data/astrbot_plugin_quote_topics/index.sqlite3`，只记录平台/机器人/群或用户标识、消息编号、对话编号、归属和时间；不另存聊天正文。
聊天内容仍在 AstrBot 数据库。请将 AstrBot 数据与本插件数据**一起备份**，最好在停止服务后备份，避免漏掉 SQLite WAL 内容。

消息关联使用平台实例、机器人身份、聊天类型和群号/用户号作为复合范围。不会仅凭消息编号跨会话查询。
读取对话后会再次验证其数据库归属；话题删除后不自动重建。

同群的锁保持到整条消息任务结束，包括历史写入和发送处理。异常、取消也会释放锁，正常结束后恢复此前的会话选择。
模型或发送失败时保留原始提问关联，用户可引用原始提问重试。平台重复投递同一个消息编号不会再次调用模型。
如果进程被强制终止，原生会话选择可能来不及恢复；重新启用后仍按引用规则选题。切回原有连续聊天模式前可通过 AstrBot 对话管理确认所选对话。

## 开发与验证

无需额外运行时依赖，使用 AstrBot 已安装的飞书 SDK 和 Python 标准库。

```sh
python -B -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

真实组件集成检查需要在隔离的测试环境中安装 AstrBot 4.28.0，然后运行：

```sh
python -B tests/integration_offline.py
```

该脚本使用临时数据目录、真实 ConversationManager、SQLite 和 Lark SDK，并禁止 socket 连接；不会读取生产配置、连接飞书或调用模型。
它验证创建、跨成员恢复、独立历史、原会话选择恢复，以及索引重新加载。它不是完整模型管道或飞书端到端测试。

上线验收请见 [验收清单](ACCEPTANCE.md)，实现依据和兼容约束见 [架构说明](ARCHITECTURE.md)。
